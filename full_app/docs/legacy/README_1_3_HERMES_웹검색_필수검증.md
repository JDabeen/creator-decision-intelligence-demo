# Hermes 웹 검색 0회 문제 — v1.3

## 지난 실행의 정확한 상태

- Docker 실행 성공, Hermes API 연결 성공, Hermes GPT 비평문 생성 성공.
- **실제 `web_search` 호출: 0회**, 검색 결과 확인: 0회.
- 결론: **외부 자율 웹 조사 성공 X**. 기존 자막/시장 자료를 참고한 비평만 생성됐습니다.

## 왜 이전 버전은 잘못된 성공처럼 보였나

1. `/v1/toolsets`에서 활성 `web_search`가 필수인지 검사하지 않았습니다.
2. 큰 대본 프롬프트에 "검색해 봐"라고 지시만 하고, 검색 0회여도 Draft B를 완성했습니다.
3. 웹 제공자 설정 파일(`config.yaml`)을 수정해도, 이미 실행 중인 Docker 컨테이너가 새 설정을 읽지 못하는 상황이 생길 수 있었습니다.

## v1.3 변경

- 독립 재설계 및 Hermes 주제 선별 단계에서 **실제 웹 조사 전용 실행**을 먼저 호출합니다.
- API 도구 목록에서 `web_search`가 빠져 있으면 명확한 오류로 중단합니다.
- 함수 호출과 도구 응답, **실제 URL 출처**가 하나라도 검증되지 않으면 주제/대본 결과를 완료로 표시하지 않고 중단합니다.
- 검색이 성공하면 실제 출처와 간결한 연구 결과를 Draft B 비평 단계에 전달하고, 수행 내역을 A/B 화면에서 확인할 수 있습니다.
- 필요한 경우 설정 변경을 감지해 Docker 컨테이너만 다시 만들고 캐시/프로젝트 데이터는 유지합니다.
- 실패 원인별 오류를 화면에 출력하므로 로그 없이 막연하게 "Hermes 정상"이라고 판단하지 않습니다.

## 실행

1. ZIP을 새 폴더에 압축 풀고, 이전 폴더 `.env` 파일을 복사합니다. 프로젝트 캐시는 기존 방식으로 유지됩니다.
2. Docker Desktop에서 Engine running인지 확인하고 `0_START_WITH_HERMES.bat` 실행.
3. Draft A 화면 → Hermes 비평 섹션 → `② 웹 검색 실제 실행 테스트` 실행.
4. 성공 시 검색 횟수와 URL이 표시됩니다. 이후 `독립 재설계 · 새 대본` 선택.
5. 실패 시 구체적 오류 내용을 확인합니다. **성공했다고 표시되는 화면과 실제 웹 조사 기록은 별개**입니다.

## 무료 웹 검색과 예비 방법

공식 Hermes에는 API 키 없이 사용할 수 있는 검색 제공자가 있습니다. 다만 **사용자 PC에 설치된 Hermes 이미지가 해당 기능을 실제 지원하는지, 네트워크에서 검색이 되는지는 실행 후에만 확인할 수 있습니다**. 코드 테스트는 실제 네트워크 성공을 보증하지 않습니다.

첫 테스트가 실패하면 기존 `.env`에 다음 중 **하나**를 추가하고 앱을 다시 실행할 수 있습니다.

```dotenv
YRA_HERMES_WEB_BACKEND=firecrawl
```

또는 공식 API 키가 있는 경우(선택):

```dotenv
TAVILY_API_KEY=발급받은_키
YRA_HERMES_WEB_BACKEND=tavily
```

`EXA_API_KEY`와 `YRA_HERMES_WEB_BACKEND=exa` 조합도 가능합니다. 기존 YouTube/Supadata API와는 다른 서비스입니다. 추가 검색 서비스의 무료 한도/유료 과금 조건을 직접 확인하세요.

**실패했다고 터미널·파일 접근 권한을 풀거나, 보안 검사를 우회하지 마세요.**

## 명확한 검증 한계

제작 환경에서 Windows Docker 컨테이너, 실제 OpenAI 계정, 검색 서비스 네트워크를 통합 호출할 수는 없었습니다. 오프라인 테스트는 도구 흔적을 제대로 식별하고 오작동을 차단하는지를 검증한 것입니다. 실제 성공은 `웹 도구 응답 >=1`과 출처 URL이 나오는 것으로 확인합니다. 검색 자체가 성공해도 그 근거의 신뢰성이나 미래 영상 조회수가 증명되지는 않습니다.
