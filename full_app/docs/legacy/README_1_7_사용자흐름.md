# v1.7 · 주제 우선 4단계 UI

## 변경 이유

이전 버전에서는 주제 추천 A, Hermes 주제 추천 B, 심층 조사, 대본의 결과가 같은 페이지에 차례로 누적되어 현재 진행 단계를 알기 어려웠습니다. **주제 선정이 제품의 핵심**이므로 개별 작업을 하나의 선형적인 사용자 흐름으로 재구성했습니다.

## 앱에서 보이는 단 4단계

**① 주제 찾기:** `다음 주제 찾기` 버튼 한 번으로 기존 AI(A) 추천을 만든 뒤 Hermes(B) 독립 웹 조사를 실행합니다. Hermes는 A가 추천한 주제 목록을 보지 않으며, 기존 시장 데이터·채널 데이터만 공유합니다. 각 모델의 시장 수요 판단은 증거가 아니라 평가 가설입니다. Hermes가 실패해도 A 결과는 유지합니다. 이전 비교 실험은 재실행 없이 불러올 수 있습니다.

**② 비교·선택:** A/B 주제 각각 3개(최대 6개)를 짧게 보여줍니다. 주제 하나를 고르면 이유·위험·출처를 필요한 경우 펼쳐서 볼 수 있습니다. 다음 버튼은 **`이 주제로 더 찾기 →`** 하나입니다. Hermes가 실패했다면 `Hermes 조사만 재시도` 버튼이 B 칸에만 나타납니다.

**③ 심층 조사:** 앞에서 선택한 주제 하나만 다룹니다. 기존 YouTube API 및 실제 경쟁 영상 자막을 조사하고 Research Coverage Gate를 그대로 적용합니다. 영상 구성 방향 하나를 선택한 뒤 **`이 방향으로 대본 만들기 →`**를 누르면 다음 단계로 갑니다. 이 단계의 구성 방향 후보가 원래 선택한 주제에서 너무 벗어나면 제작하지 않고 돌아가 다른 주제를 고를 수 있습니다.

**④ 대본:** 선택적으로 촬영 대본을 작성하고 피드백하거나 다운로드합니다. 기존 연구·설계·Hermes 추가 비평 기능을 유지합니다. 대본을 만들지 않아도 주제 조사/선정은 완료한 것입니다.

상단의 단계 버튼을 누르면 **저장된 실행 상태를 화면에서 다시 보여줄 뿐**, 시장 검색/API 작업을 다시 실행하지 않습니다. 다음 단계는 필요한 데이터가 실제로 있을 때만 열립니다. 각 단계는 별도의 화면이므로 아래쪽으로 누적되지 않습니다.

## 데이터 및 호환성

- 기존 `.env`, 캐시, `youtube_consultant_data` 폴더, Hermes Docker 설정, 채널 데이터, `.bat` 파일, 기존 보고서 생성 및 `human_selection.json` 저장 기능은 변경하지 않았습니다.
- 호환 버전: **v1.6.1 브라우저 권한 수정본** 위에 설치 가능합니다.
- 앱만 수정한 패치에는 `app.py`, `workflow_ui.py`, `BUILD_VERSION.txt`가 들어 있습니다. 해당 파일들을 **`0_START_WITH_HERMES.bat`이 있는 프로그램 폴더에 직접 덮어써야** 합니다.
- 주제 비교 저장 위치는 기존과 같이 `youtube_consultant_data/topic_experiments`입니다. 연구 실행 시 네트워크와 OpenAI API 사용 비용이 발생할 수 있습니다.
- 사용자 시스템의 Hermes 실제 웹 조사 여부는 현장 실행으로 검증해야 합니다. 앱 화면 분리 테스트와 Hermes 통합 검색 성공은 다른 검사입니다.

## 포트폴리오 설명

기술 구성은 기존 YouTube API + RAG 추천 기준선(A)과 Docker 격리 Hermes 독립 웹 조사(B)입니다. 일반적인 YouTube 시청자 A/B 실험과 달리 **두 연구 접근법의 주제 추천을 사람이 비교하고 선택**하는 워크플로입니다. 운영 시에는 수집 자료의 출처·주제 선정 근거·중복 위험 및 선택 기록을 남깁니다.
