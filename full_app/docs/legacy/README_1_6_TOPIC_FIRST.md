# v1.6 · **다음 주제** 먼저, 대본은 선택 후

## 목적

실제 YouTube 채널 `틀린영어`의 *다음 콘텐츠를 무엇으로 정할지* 판단하는 의사결정 지원 도구입니다. 대본 A/B 비교가 핵심 기능이 아닙니다.

## 사용자 흐름 (한 화면, 간단한 순서)

1. **`0_START_WITH_HERMES.bat`** 실행 → `시장과 내 채널에서 다음 콘텐츠 찾기` 클릭.
2. **A: 기존 AI 추천 3개**를 확인. 기존 YouTube Data API, 채널 데이터, RAG/시장 분석은 그대로 유지합니다.
3. **`Hermes 독립 웹 조사 → 다음 주제 3개 비교`** 클릭. Hermes는 A가 제안한 제목이나 Draft A를 받지 않습니다. 시장 영상·내 채널 실적·기존 공개 대본 일부만 받아 웹 조사 후 **B: 주제 3개**를 별도로 추천합니다.
4. A/B 추천 **총 6개 후보의 시청자 문제·근거·중복 위험**을 비교하여 사람이 하나를 선택합니다. 증거가 부족하면 아무것도 선택하지 않아도 됩니다.
5. 선택한 주제로 **Deep Research**: 관련 경쟁 영상 자막, 설명 방식, 예시, Knowledge Gap을 다시 조사 → 콘텐츠 방향 검토 → **대본 생성(선택 기능)**. 기존 Transcript Coverage Gate 유지.
6. 업로드 이후의 조회수·노출·시청지속/전환 실측치는 수동으로 추적합니다. 이 추천 실험 자체는 **실제 시청자 A/B 테스트가 아닙니다.**

## 실제 검증 / 실패 처리

- Hermes의 API 연결 성공은 웹 조사 성공이 아닙니다. **실제 웹 도구의 호출·응답·URL 확보**가 확인되지 않으면 B를 생성하지 않고 중단합니다. A 추천은 그대로 사용 가능합니다.
- Hermes가 임의로 적은 외부 URL은 채택하지 않습니다. **도구 응답에서 얻은 URL 목록과 일치하는 링크만** 표시합니다. 일치하는 URL도 해당 주제의 수요를 증명하지 않으며 내용의 정확성은 별도 확인 대상입니다.
- 시장 후보 표본은 편향될 수 있고, 추천된 조회수 상한/미래 성과를 입증하지 않습니다.
- B는 공유된 시장 관측값의 **부분집합** + 추가 웹 조사로 추천합니다. 따라서 이것은 LLM 모델의 동등 조건 우열 실험이 아니라, 서로 다른 **추천 방식**의 비교입니다.
- 과거 대본 일부와 시장 메타데이터가 AI 서비스로 전송됩니다. **개인정보·비공개 대본은 입력하지 마세요.** Windows 개인 문서/바탕화면을 Hermes Docker에 마운트하지 않습니다. API 키는 전용 데이터 폴더/환경 변수에서 취급됩니다.

## 포트폴리오 재현 자료

프로젝트 데이터 폴더 `youtube_consultant_data/topic_experiments/<실험ID>/`에 자동 저장:

| 파일 | 용도 |
|---|---|
| `evidence.json` | 공유한 시장·내 채널 관측값 및 규모 |
| `baseline_a.json` | 기존 AI의 추천·실제 시장 근거 |
| `hermes_web.json` | 실제 웹 호출/출처/응답 기록 (성공 시) |
| `hermes_topics_b.json` | Hermes의 독립 주제 3개 (성공 시) |
| `comparison.json` | A/B 비교에 표시한 자료와 한계 |
| `human_selection.json` | 사람이 최종 선택한 주제·선정 방식 |
| `manifest.json` | 코드 버전, evidence 해시, 성공/실패 상태 |

실패 기록에도 `manifest.json`과 기존 A 후보가 남습니다. 개인 데이터 및 API 키는 GitHub에 업로드하지 마세요.

## 1차 완성 조건

**A 추천 3개 → Hermes 실제 웹 도구 응답 + B 추천 3개 → 사용자가 주제 선택 → Deep Research → 촬영 가능한 대본 1개 → 실행 기록**.

이 한 바퀴를 네 PC에서 실제로 완주한 뒤, 기능을 동결하고 README/데모 영상으로 마무리합니다. 이후 업로드 성과는 후속 검증 데이터입니다.

## 오프라인 코드 테스트

`python -m unittest discover -s topic_tests -v` / `python -m unittest discover -s hermes_integration/tests -q` / `python -m unittest discover -s hermes_experiment/tests -q`.

오프라인/모의 테스트는 **Windows Docker/Hermes 실제 조사 성공을 증명하지 않습니다.**

프로그램을 다시 시작했다면 홈의 **`지난 주제 A/B 비교 이어보기`** 버튼으로 마지막 완료 실험을 불러올 수 있습니다. API를 다시 호출하지 않습니다. 다만 이전과 동일한 시장 조사 기준 시점의 스냅샷이며 현재 데이터로 자동 갱신되지는 않습니다.
