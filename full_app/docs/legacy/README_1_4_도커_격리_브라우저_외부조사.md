# v1.4 — Hermes Docker 내부 웹 조사

## 무엇이 달라졌나

- Hermes의 API 서버 도구 목록에 `web` 및 **Docker 내부 `browser`** 툴셋을 허용했습니다.
- 터미널, 파일 수정, 코드 실행, Windows UI 직접 조작은 계속 비활성화합니다.
- 실제 검색 (`web_search`/`web_extract`) 또는 **브라우저 방문+화면 읽기** (`browser_navigate` + `browser_snapshot`)가 실행됐을 때만 외부 조사 근거로 인정합니다.
- 확인 가능한 HTTP(S) 출처 URL이 없으면 성공으로 처리하지 않습니다.
- 불필요한 Docker 재설치 없이 설정 변경 시에만 Hermes 컨테이너를 갱신합니다.
- 기존 유튜브 앱, 시장 자막 캐시, API 키 파일은 ZIP에 포함되지 않습니다.

## 보안 경계

기본 Compose 설정에는 **전용 Hermes 상태 디렉터리**(`/opt/data`)만 마운트됩니다. 사용자의 Windows 문서·사진·바탕화면·프로젝트 폴더, 호스트 브라우저 프로필, Docker 소켓을 연결하지 않습니다. API 포트는 Windows의 `127.0.0.1:8642`에만 공개되고 인증 키가 필요합니다. Docker `privileged`/host networking도 사용하지 않습니다.

**절대 안전을 보장하지 않습니다.** 브라우저 툴셋은 클릭/입력까지 제공할 수 있고, 컨테이너에는 모델 API 키 및 Hermes 전용 상태 파일이 있습니다. 악성 웹 콘텐츠, 모델 판단 오류, 설정 오류 또는 취약점이 있으면 해당 정보가 유출될 수 있습니다. AI와 외부 검색 서비스로 작업 입력이 전송될 수도 있습니다. 로그인 상태의 개인 브라우저나 민감한 학원/학생 데이터는 절대 연결하지 마세요.

브라우저가 필요 없으면 기존 `.env`에 `YRA_HERMES_BROWSER=0`을 추가합니다. 그러면 `web_search`/`web_extract`만 사용하고 브라우저 툴셋은 금지됩니다.

## 사용법

1. ZIP을 **별도 폴더**에 압축 해제하고 이전 `.env`를 복사합니다.
2. Docker Desktop이 `Engine running`인지 확인하고 `0_START_WITH_HERMES.bat` 실행.
3. 유튜브 앱 Draft A → `웹 검색 실제 실행 테스트` 버튼 클릭.
4. 외부 조사 도구의 실제 호출·응답과 HTTP(S) URL이 표시되는지 확인합니다.
5. **0회나 오류면 웹 조사 실패입니다.** 실제 Windows Docker/Chromium 동작은 이 환경에서 검증할 수 없었습니다.

## 포트폴리오 표현

'Windows 호스트 권한을 주지 않은 Docker 컨테이너에서 Hermes의 웹 조사 도구를 실행했고, 실제 도구 실행 기록과 출처 URL을 검증하도록 설계했습니다. 다만 컨테이너 격리는 절대적 보안 경계가 아니며, 외부 API로 전송되는 입력과 모델 API 키 관리에 주의했습니다.'
