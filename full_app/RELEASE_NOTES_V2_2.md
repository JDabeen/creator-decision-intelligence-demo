# v2.2 · 증거 기반 안정화 릴리스

## 문제 해결

- YouTube `search.list` 응답에서 API 한도 초과(HTTP 403/429)를 감지하면 뒤따르는 검색을 중지하고 **이미 확보한 관련 영상 ID**로 제한된 조사를 진행합니다.
- 같은 검색어·조건은 24시간 영상 ID 검색 캐시로 재사용합니다. 단일 실행에서 먼저 확보한 후보도 잃지 않습니다. `videos.list`를 통한 공개 통계 확인은 별도로 진행합니다.
- 기존 시장 영상 ID가 없다면 **근거가 없다고 표시하고** 조사 준비 상태를 false로 유지합니다. AI 대본을 만들거나 성공한 척하지 않습니다. 원본 Transcript 검증 기준은 유지합니다.
- API 요청 URL/토큰/Windows 내부 traceback을 사용자 오류 화면에서 제거합니다. **이전에 유출한 키는 Google Cloud에서 교체·제한**하세요.
- **더 알아보기 ≠ 제작 확정**. 상세 조사 후 '제작 확정'을 눌렀을 때만 의사결정·사전 판단 기록을 남깁니다. 탐색 로그는 별도의 `topic_explorations.json`에 기록합니다. 기존 기록은 삭제하지 않습니다.
- 측정된 **내 영상 누적 조회수·댓글 절대 수, 외부 근거 영상, 동일 배치 내 Trends 변화**만 그래프로 표시합니다. 영상 ID가 매칭되지 않으면 그래프 대신 자료 부족 메시지를 보여줍니다.
- SerpApi가 연결되어 있으면 최초 추천 전 **탐색 검색축의 상대 관심도**를 조사하고 A/Hermes에 전달합니다. 최종 추천 6개 후보의 SerpApi 결과는 이후 추가 수집됩니다. 후행 데이터가 이미 정해진 순위에 반영됐다고 주장하지 않습니다.

## 범위와 한계

- 24시간 캐시는 API 통계의 실시간성을 보장하지 않으며, Google 프로젝트에 남은 공식 할당량을 알 수 없습니다. 프로젝트 한도는 Cloud Console에서 확인하세요.
- 저장된 영상·댓글 자료에 대한 YouTube API 서비스 정책(보존 기간·갱신·파생 분석·접근권한)을 실사용 방식에 맞게 별도 점검해야 합니다. **GitHub 공개 패키지에는 실제 수집 데이터를 넣지 마세요.**
- 과거 `topic_choices.json`에 '더 알아보기'로 이미 기록된 항목은 자동으로 제작 확정으로 해석하거나 삭제하지 않습니다. 마이그레이션을 하지 않고 '레거시·확정 여부 미검증'으로 취급하세요.
- **v2.1 ZIP을 기반으로 수정한 전체 설치본**입니다. Windows/Docker/실제 외부 API End-to-End는 실사용 PC에서 확인해야 합니다.
- 전략 기록은 바탕화면 `YT_Channel_Strategy`, 그 외 캐시는 기존 바탕화면 `youtube_consultant_data`에 유지합니다. ZIP 압축 교체 시 폴더를 삭제하지 마세요.

- Hermes 웹 도구에서 실제 발견해 해당 후보에 인용한 YouTube 영상 URL은 ID를 추출해 검색 대신 직접 조회합니다(단, 출처의 존재는 수요 증명이 아님).

- `10_BACKUP_STRATEGY_DATA.bat`: 바탕화면 전략 기록의 개인 백업을 별도 저장합니다. 백업에는 비공개 상담 내용이 있으므로 공개 금지.

- 백업 스크립트는 `YT_Channel_Strategy` 및 `youtube_consultant_data/topic_experiments`, 콘텐츠 메모리도 포함합니다. 복구 시 보존할 데이터 폴더를 압축 해제해야 합니다. **자동 복원은 구현하지 않았습니다.**

- 설치 ZIP은 `.env.example`만 포함합니다. 기존 실제 `.env`는 새 폴더에 직접 복사하세요. 공개 데모는 가상 데이터만 사용합니다.

## 2026-10-31 · Hermes 전략 경로 출력 복구 핫픽스 (v2.2 유지)

- Hermes 주제의 `strategy_route`가 `인접확장`/`신규실험형` 등 동일 의미의 표기 차이인 경우만 허용된 세 값으로 정규화합니다.
- 누락되거나 의미가 모호한 경로는 기존 추천 본문을 수정하지 않고 Hermes에 **전략 경로 필드만 한 번** 재확인합니다. 재확인 실패 시 B 결과는 여전히 미확정이며 A 추천과 원래 자료는 유지됩니다.
- 문제 추적을 위해 주제 응답 원문을 `youtube_consultant_data/topic_experiments/<실행 폴더>/hermes_raw_topics.txt`에 기록합니다. 보정이 발생하면 원문/보정 응답도 별도 파일로 남깁니다. 이 기록은 개인 데이터이므로 공유·공개 저장소 업로드에 주의하세요.
- 조정 대상은 `topic_experiment.py`와 오프라인 회귀 테스트뿐입니다. `bat`, `.env`, `requirements.txt`, 도커/캐시, Research/Transcript Gate 동작은 변경하지 않았습니다.
- 모의 Hermes 응답과 정적/오프라인 테스트 통과. **사용자 Windows/실제 Hermes API에서의 E2E 성공을 의미하지는 않습니다.**

## 2026-10-31 · Hermes 조사 출처 연결 핫픽스 (v2.2 유지)

- 원인: Hermes의 추천 `evidence_urls`와 웹 도구가 실제 반환한 URL을 문자열 그대로 비교해, 같은 YouTube 영상의 공유 링크/일반 링크, 추적 파라미터 등에서도 불일치가 날 수 있었습니다. 출처를 하나도 인용하지 않을 때는 추가 검색 후 추천 전체를 다시 생성해 기존 후보를 잃을 위험도 있었습니다.
- 수정: 동일한 **실제 YouTube 영상 ID** 및 추적 파라미터 차이처럼 무해한 URL 표기 차이만 매칭합니다. 새로운 링크를 만들거나 다른 영상을 동일 출처로 취급하지 않습니다. 화면에는 웹 도구가 관측한 원래 URL을 표시합니다.
- 추가 검색 후 Hermes의 **원래 주제/순위/전략을 보존**하고, 확인된 출처 목록의 번호만 고르는 짧은 보정 요청 1회를 수행합니다. 출처가 해당 주제와 무관하면 `[]`로 답하도록 요청합니다. 출처가 계속 0개라면 B 확정을 중단하고 A를 보존합니다.
- `topic_experiments/<실행 폴더>/hermes_source_match_diagnostic.json`에 후보별 연결된 출처 수와 상태를 저장합니다. `hermes_citation_repair.txt`는 보정 모델 응답 원문입니다. 해당 기록과 `.env`는 공개 저장소에 올리지 마세요.
- 변경 범위: `topic_experiment.py`, 회귀 테스트 및 이 릴리스 노트. 기존 bat, 도커 설정, requirements, cache, 기존 데이터 폴더, Transcript Gate는 변경하지 않았습니다.
- 오프라인 회귀 검사 통과. 실제 Windows / Hermes 웹 도구 / 사용자 계정 E2E는 별도로 실행해 확인해야 합니다.
