Hermes v1.4 — Docker 안에서 인터넷 조사하기

네 컴퓨터의 Chrome이나 Windows 파일을 조작하는 방식이 아닙니다.

[연결되지 않은 것]
- Windows 문서, 사진, 바탕화면, 유튜브 프로젝트 데이터 폴더
- Windows Chrome 프로필·로그인 쿠키
- Docker 제어 소켓(/var/run/docker.sock)
- Docker privileged / 호스트 네트워크

[연결된 것]
- Hermes만 사용하는 설정·상태 폴더: %USERPROFILE%\youtube_consultant_hermes_data
- 실행에 필요한 OPENAI_API_KEY, 선택한 검색 제공자 API 키
- localhost:8642로 인증된 HTTP API, 외부 인터넷 접속

브라우저 사용 범위: 이 옵션은 Hermes의 browser toolset 전체를 활성화하므로
단순 읽기뿐 아니라 클릭·입력 도구도 활성화될 수 있습니다. 지시문으로는
비공개 정보 접근이나 폼 제출을 금지했지만, 기술적인 강제 차단은 아닙니다.
따라서 계정 로그인이 필요한 사이트를 사용하지 않고 개인 파일을 제공하지 않아야 합니다.

중요: Docker는 완벽한 개인정보 보호 장치가 아닙니다. Hermes가 외부 사이트를 읽는 동안
프롬프트와 입력한 연구 자료가 외부 AI·검색 제공자에 전송될 수 있습니다.
컨테이너가 접근할 수 있는 전용 설정 폴더와 API 키 역시 민감합니다.
로그인이 필요한 사이트, 개인 메일, 내부 회사 문서, 비공개 학원 학생 데이터는 입력하지 마세요.

안전한 웹 조사 검증 방법
1. 기존 버전 유지, 새 폴더에 압축 풀고 이전 .env만 복사
2. Docker Desktop Engine running 상태에서 0_START_WITH_HERMES.bat 실행
3. 화면에서 'Hermes가 실제로 작동하는지 확인하기' → '웹 검색 실제 실행 테스트' 클릭
4. 실제 외부 도구 호출 횟수 >= 1, 응답 >= 1, http(s) 출처 URL 확인
5. 0회·오류라면 성공이 아님. 빈 결과를 시장 검증 완료로 표시하지 않음

브라우저를 끄고 싶으면 .env에 YRA_HERMES_BROWSER=0 을 추가한 뒤 다시 실행하세요.
Docker 엔진의 격리는 유지하며 Windows 전체 권한은 요구하지 않습니다.

테스트 한계: 이 개발 환경은 Windows Docker가 없어 실제 Chromium/검색 라이브 테스트를
완료할 수 없습니다. 모의 테스트는 권한 목록과 응답 파싱의 안전 판정을 검증합니다.

[v1.6.1 브라우저 권한 검사 수정]
- Hermes 공식 브라우저 도구인 browser_vault_enter_code/fill/list/save_login/unlock 5개는
  브라우저 켤 때 도구 목록에 나타나므로, 알 수 없는 도구라고 즉시 중단하던 오류를 수정했습니다.
- 이것은 해당 도구가 실행되지 못하도록 따로 차단했다는 뜻이 아닙니다.
  Hermes에서는 브라우저 도구 묶음을 허용하면 로그인 관리 도구도 같이 노출됩니다.
- Windows Chrome 로그인/쿠키는 공유하지 않으며 기존 파일/터미널 접근 차단 유지.
- 브라우저에게 비밀번호, 개인정보, 계정 로그인을 제공하지 마세요.
- 컨테이너 내 Hermes 설정 폴더 및 API 키는 접근 가능하고 인터넷 전송 위험은 남아 있습니다.
- 실제 웹 검색과 외부 출처 확보 여부는 앱의 '웹 검색 실제 실행 테스트'에서 따로 확인.
- 이전 .env에 YRA_HERMES_BROWSER=0을 넣었다면 1로 바꾸거나 삭제해야 브라우저가 켜집니다.
